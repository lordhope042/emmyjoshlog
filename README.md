# Emmyjosh customer frontend – offline font and catalogue request fix

## Files
- `js/app.js`
- `js/numbers.js` (retained from the previous customer-side patch)
- `css/style.css`

## Changes
- Removed the remote Google Fonts import; the interface now uses local/system font fallbacks and works without a network font request.
- Added an in-flight guard to number catalogue loading and marks the catalogue route as loaded before rendering.
- Removed the second explicit catalogue request after number-filter submission; rendering is the single request trigger.
- Preserved the prior number-order recursion guard and yellow SVG social-card work.

## Important operational note
A 502 from `/api/v1/providers/numbers/catalog` or `/api/v1/providers/logs/catalog` is generated by the backend provider route when the upstream provider request fails or the provider configuration is not ready. This frontend patch prevents duplicate catalogue requests but cannot restore external provider connectivity while the backend host is offline. Check the backend process/network and the relevant provider environment variables (token, enabled flag, currency, NGN rate, retail markup mode/value). Do not expose tokens in browser code or screenshots.

A 401 from `/api/v1/auth/me` means there is no valid customer session; sign in again if the customer expected to be authenticated. A 401 on a signed-out landing visit is expected.
